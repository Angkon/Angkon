# GitHub portfolio design

Date: 2026-10-23
Status: scaffolding drafted and verified; repositories not yet created because the Claude GitHub integration was not permitted to create them

## Goal

Organize github.com/Angkon as a research portfolio. Everything produced as part of research, meaning projects, agent skills for Claude Code and Codex, and methods derived with or without agents, lives in its own repository, and the profile page indexes them.

## Structure: hub and spokes

- **Hub:** `Angkon/Angkon`, this repository. Its README is the profile page and the index.
- **Spokes:**
  - One repository per research project, created from `research-project-template`.
  - `agent-skills`: every skill, in one repository. The `SKILL.md` format is read by both Claude Code and Codex, so one copy serves both tools.
  - `research-methods`: every method, in one repository, one folder per method.
  - `research-project-template`: a GitHub template repository for new projects.

## Alternatives considered

- **Monorepo.** Simpler to maintain, but the request was for separate repositories, and projects need their own issues, CI, and citations.
- **One repository per skill and per method.** Too many small repositories to browse, and the catalog tooling would be duplicated in each. A skill or method that grows large can still be split out later.
- **Separate `claude-skills` and `codex-skills`.** Rejected because both tools read the same `SKILL.md` format. A split would duplicate every skill.

## Conventions

- **Naming.** Repository names are lowercase and hyphen-separated. Skill and method folder names equal their frontmatter `name`.
- **READMEs.** Every project README has the same sections, in the order given by the template.
- **Provenance.** Method frontmatter records `origin`, `agent`, `model`, `skill`, and `derived`. Skill frontmatter records `metadata.author` and `metadata.origin`.
- **Catalogs.** The tables in `agent-skills` and `research-methods` are generated by `scripts/build_catalog.py` and checked in CI, so they cannot go stale.
- **Topics.** `research-project`, `agent-skill`, `research-method`, set in each repository's settings.
- **Licenses.** MIT on the tooling repositories (skills, methods, template). Projects choose their own.

## Decisions still open

2. **Profile text.** Research focus, group, and position in the profile README are placeholders.
3. **Private repositories.** SMURF is named on the profile although private; MIME is an empty placeholder and is not listed.
4. **Licenses.** MIT is a placeholder choice.
5. **Template flag.** `research-project-template` should be marked as a template repository in its settings so "Use this template" appears.

## Maintenance

- New project: use the template, then add a row to the portfolio map.
- New skill or method: add a folder, run `scripts/build_catalog.py`, commit. CI fails if the catalog is stale or a frontmatter field is missing.
